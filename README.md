## 1. ภาพรวมโปรเจกต์

### โจทย์

ฝ่ายทรัพยากรบุคคลและผู้วางนโยบายมักรู้ว่าตลาดแรงงาน "ขาดคน" ก็ต่อเมื่อเกิดปัญหาแล้ว โปรเจกต์นี้พยายามตอบคำถามว่า

> จากข้อมูล 3 เดือนล่าสุด เดือนหน้ากลุ่มอาชีพนี้จะอยู่ในภาวะขาดแคลน สมดุล หรือคนล้นตลาด?

### แนวคิด

เปรียบเทียบ **อุปสงค์** (ตำแหน่งงานว่าง — Vacancies) กับ **การจับคู่สำเร็จ** (ผู้ได้รับการบรรจุ — Appointments) ในรูปของผลต่าง (Gap)

```
Gap = Vacancies − Appointments        (ทั้งสองค่า Normalize ให้อยู่ในช่วง 0–1)

Gap ≥ +0.15  →  Severe_Shortage  (ขาดแคลนรุนแรง)
Gap ≤ −0.15  →  Oversupply       (คนล้นตลาด)
อื่น ๆ        →  Balanced         (สมดุล)
```

### สิ่งที่โน้ตบุ๊กทำ

| ขั้น | สิ่งที่ทำ |
|---|---|
| 1 | โหลดข้อมูล 3 ตาราง (ผู้สมัคร, ผู้บรรจุ, ตำแหน่งงานว่าง) ของกรมการจัดหางาน รายเดือน ม.ค. 2014 – ส.ค. 2026 |
| 2 | ทำความสะอาดข้อมูล แปลงวันที่ ตัดกลุ่มอาชีพที่ข้อมูลน้อย |
| 3 | Normalize (Min-Max), แก้ Structural Break ปี 2016/2020 และจัดการ Outlier |
| 4 | สร้าง Lag Feature ย้อนหลัง 3 เดือน และกำหนดคลาสเป้าหมายจากเกณฑ์ Gap |
| 5 | เทรนและเปรียบเทียบ 2 แนวทาง: **Regression + Rule-based** และ **Direct Classification (Random Forest)** |
| 6 | ปรับโมเดล (Ridge, class_weight) และเลือกโมเดลที่ดีที่สุด |

ประเมินบนชุดทดสอบ 30 เดือน (มี.ค. 2024 – ส.ค. 2026):

| โมเดล | Accuracy | Macro F1 | F1 Balanced | F1 Oversupply | F1 Severe_Shortage |

| Linear Regression + Rule-based | 0.57 | 0.54 | 0.57 | 0.29 | 0.78 |
| Random Forest (เริ่มต้น) | 0.53 | 0.40 | 0.61 | 0.00 | 0.59 |

เกณฑ์เทียบเคียง (Baseline) ที่คำนวณเพิ่มเติมตอนจัดทำเอกสารนี้ (ไม่ได้อยู่ในโน้ตบุ๊ก):

## 6. ขั้นตอนการทำงาน (Pipeline)

### 6.1 โหลดและเลือกข้อมูล

อ่านทุกชีตด้วย `sheet_name=None, skiprows=1` แล้วเลือกชีต `CSV` ซึ่งอยู่ในรูปแบบแถว = เดือน, คอลัมน์ = อาชีพ และใช้ปี ค.ศ.

### 6.2 ทำความสะอาด

| งาน | รายละเอียด |
|---|---|
| แปลงวันที่ | รวม `Year` + `Month` (เช่น `2014-Jan`) เป็นคอลัมน์ `Date` ชนิด datetime แล้วตัด `Year`, `Month` |
| Transpose | ให้อาชีพเป็นแถว และ `Date` เป็นคอลัมน์ |
| เติมค่าว่าง | `NaN` → `0` |
| ตัดกลุ่มอาชีพ | ตัด `0` (ทหาร), `X` (จัดประเภทไม่ได้) เพราะข้อมูลน้อยเกินไป, `T` (ผู้ฝึกงาน) เพราะไม่จำเป็นต่อการวิเคราะห์ และ `Total` เพราะเป็นผลรวม |
| ตัดช่วงเวลา | ตัดตั้งแต่ ก.ย. 2026 เพราะยังไม่มีข้อมูลครบทั้ง 3 ตาราง → เหลือ 152 เดือน |

### 6.3 ตรวจสอบความสมบูรณ์

- วันที่ของทั้ง 3 ตารางตรงกันทั้งหมด
- ไม่มีเดือนขาดหายในช่วงเวลา
- ไม่มีเดือนที่ข้อมูลเป็น 0 ทุกอาชีพ

### 6.4 Normalize และตรวจดูการกระจาย

ใช้ `MinMaxScaler` แบบ **แยกรายอาชีพตลอดช่วงเวลา** (ค่าต่ำสุด = 0, สูงสุด = 1) แล้วพล็อต Stacked Area Chart เพื่อดูลักษณะข้อมูล จึงพบความผิดปกติ 2 แบบ

1. **Structural Break** ในข้อมูลผู้สมัคร/ผู้บรรจุ — ระดับค่าเปลี่ยนฐานก่อน ก.ค. 2016 และตั้งแต่ ม.ค. 2020
2. **ยอดแหลมผิดปกติ** ในข้อมูลตำแหน่งงานว่างช่วงปี 2020

### 6.5 Data Smoothing

| ชุดข้อมูล | วิธีจัดการ |
|---|---|
| **Vacancies** | Cap (Winsorize) ที่ Percentile 90 ของแต่ละอาชีพ แล้ว Normalize |
| **Applicants, Appointments** | ฟังก์ชัน `process_two_structural_breaks` — ปรับสเกลช่วงก่อน ก.ค. 2016 และช่วงตั้งแต่ ม.ค. 2020 ให้อยู่ในฐานเดียวกับช่วงอ้างอิง ปี 2017–2018 → Cap ที่ Percentile 98 → Normalize |

รายละเอียดการปรับสเกล: ช่วงก่อน ก.ค. 2016 คูณด้วย (ค่าเฉลี่ย 2017–2018 ÷ ค่าเฉลี่ยก่อน 2016) และช่วงตั้งแต่ ม.ค. 2020 คูณด้วย (ค่าเฉลี่ย 2017–2018 ÷ ค่าเฉลี่ย 2021–2023) ทำแยกรายอาชีพ

### 6.6 จัดรูปแบบสำหรับ Machine Learning

Transpose กลับให้ **เดือนเป็น index และอาชีพเป็นคอลัมน์** เรียงตามเวลา (ตัวแปร `df_applicant_ml`, `df_appointment_ml`, `df_avaliable_ml` ขนาด 152 × 9)

## 7. การสร้างตัวแปรและตัวแปรเป้าหมาย

## 8. โมเดลและผลการทดลอง

### Model 1 — Regression + Rule-based

เทรนโมเดล Regression 2 ตัว เพื่อพยากรณ์ตัวเลข `Vacancies` และ `Appointments` ของเดือนถัดไป จากนั้นนำมาลบกันเป็น Gap พยากรณ์ แล้วใช้เกณฑ์ ±0.15 แปลงเป็นคลาส

| รุ่น | โมเดล | หมายเหตุ |
|---|---|---|
| เริ่มต้น | `LinearRegression` | Lag 1–3 มีค่าใกล้เคียงกัน (Multicollinearity) ทำให้น้ำหนักไม่เสถียร F1 ของ Oversupply = 0.29 |
| **ปรับแล้ว (เลือกใช้)** | `Ridge(alpha=1.0)` | ใส่ Regularization ลดผลกระทบของ Lag ที่ซ้ำซ้อนกัน |

### Model 2 — Direct Classification

ใช้ Random Forest พยากรณ์คลาสโดยตรง

| รุ่น | พารามิเตอร์ | ผล |
|---|---|---|
| เริ่มต้น | `n_estimators=100, max_depth=5` | ไม่ทายคลาส Oversupply เลย (F1 = 0.00) โน้มเอียงไปทายคลาสที่พบบ่อย |
| ปรับแล้ว | `n_estimators=200, max_depth=4, class_weight='balanced'` | Accuracy ลดลงเหลือ 0.47 และ F1 ของ Oversupply ยังเป็น 0.00 |

### เหตุผลที่เลือก Ridge + Rule-based

1. ได้ Accuracy และ Macro F1 สูงสุดในบรรดา 4 รุ่นที่ทดลอง
2. ทายคลาส Oversupply ได้บ้าง (F1 = 0.50) ในขณะที่ Random Forest ทั้งสองรุ่นทายไม่ได้เลย
3. ให้ **ค่า Gap พยากรณ์เป็นตัวเลข** ซึ่งตีความความรุนแรงได้ ไม่ใช่เพียงป้ายคลาส
4. โครงสร้างสอดคล้องกับธรรมชาติของปัญหา (อุปสงค์ − อุปทาน) และอธิบายได้ง่าย

### Feature Importance

โน้ตบุ๊กดึงค่า Feature Importance จาก Random Forest (รุ่นเริ่มต้น) เพื่อดูว่าข้อมูลย้อนหลังกี่เดือนมีผลมากที่สุด ดูกราฟที่เซลล์ท้าย ๆ ของโน้ตบุ๊ก

## 9. ตัวอย่างการใช้งานโมเดล

**Input:** ค่า Normalize แล้ว (0–1) ของ `Vacancies` และ `Appointments` ย้อนหลัง 3 เดือนล่าสุด
**Output:** สภาวะตลาดแรงงานเดือนถัดไป 1 ใน 3 คลาส พร้อมค่า Gap พยากรณ์

ตัวอย่างโค้ด (ใช้ตัวแปรที่ได้จากโน้ตบุ๊ก):

```python
vac = df_avaliable_ml['1']
app = df_appointment_ml['1']

# เรียงตามลำดับเดียวกับ feature_cols:
# Vac_Lag_1, App_Lag_1, Vac_Lag_2, App_Lag_2, Vac_Lag_3, App_Lag_3
x_next = pd.DataFrame(
    [[vac.iloc[-1], app.iloc[-1],
      vac.iloc[-2], app.iloc[-2],
      vac.iloc[-3], app.iloc[-3]]],
    columns=feature_cols
)

gap_next = ridge_vac.predict(x_next)[0] - ridge_app.predict(x_next)[0]
print(f"Predicted gap: {gap_next:.3f} -> {categorize_gap(gap_next)}")
```

### กรณีใช้งานเชิงธุรกิจ

เมื่อปิดข้อมูลสิ้นเดือน ฝ่าย HR หรือผู้วางนโยบายป้อนข้อมูล 3 เดือนล่าสุดเข้าโมเดล หากกลุ่มอาชีพใดถูกเตือนว่าเดือนหน้าจะเป็น `Severe_Shortage` ก็ตัดสินใจเชิงรุกได้ เช่น เพิ่มงบประกาศรับสมัคร ปรับเงินเดือนเริ่มต้น หรือเร่งกระบวนการสัมภาษณ์

> **ข้อควรระวังในการนำไปใช้จริง:** ข้อมูลใหม่ต้องผ่านการ Normalize และปรับ Structural Break ด้วยพารามิเตอร์ชุดเดียวกับตอนเทรน (ค่า min/max และอัตราส่วนปรับสเกลรายอาชีพ) แต่โน้ตบุ๊กยังไม่ได้บันทึก Scaler และอัตราส่วนเหล่านี้ไว้ใช้ซ้ำ

## 10. ข้อจำกัดและข้อควรระวัง

ข้อนี้เขียนขึ้นเพื่อให้ผู้อ่านตีความผลได้ตรงตามหลักฐานที่มี และเป็นหัวข้อที่ควรปรับปรุงก่อนนำเสนอ/ส่งงาน

### เกี่ยวกับข้อมูล

1. **เดือน เม.ย. 2026 ของ Appointments ว่างทั้งแถว** (NaN ทุกคอลัมน์) แต่ `fillna(0)` แปลงเป็น 0 ทุกอาชีพ แล้วถูกใช้คำนวณต่อ ทั้งที่น่าจะเป็นข้อมูลขาดหายไม่ใช่ "ไม่มีผู้บรรจุ" เดือนนี้อยู่ในชุด Test และกระทบ Lag ของเดือนถัด ๆ ไป (พ.ค.–ก.ค. 2026)
2. **ข้อมูลครอบคลุมเฉพาะผู้ใช้บริการกรมการจัดหางาน** ไม่ใช่ตลาดแรงงานทั้งระบบ
3. **ระบบเก็บข้อมูลเปลี่ยนในเม.ย. 2020** (Smart Jobs Center) การปรับ Structural Break ด้วยอัตราส่วนเป็นการประมาณ ไม่ใช่การแก้ที่ต้นเหตุ

### เกี่ยวกับการออกแบบการทดลอง

4. **ชุดทดสอบเล็ก:** 30 เดือน คลาสละ 7–14 เดือน ความต่าง Accuracy 0.63 vs 0.53 (Persistence) เท่ากับต่างกันประมาณ 3 เดือนเท่านั้น
5. **การกระจายคลาสต่างกันมากระหว่าง Train และ Test:** Train เป็น Oversupply ถึง 96 จาก 119 เดือน (81%) ส่วน Test มีเพียง 7 จาก 30 เดือน (23%) แสดงว่านิยามของ Gap เมื่อเทียบเกณฑ์ ±0.15 ไม่นิ่งตลอดช่วงเวลา
6. **โมเดลเดียว กลุ่มอาชีพเดียว:** เทรนและประเมินเฉพาะอาชีพ `1` เท่านั้น ยังไม่ได้ทดสอบกับอาชีพ `2`–`9` ทั้งที่ข้อมูลและการประมวลผลเตรียมไว้แล้ว
7. **ใช้ Test Set ช่วยตัดสินใจปรับโมเดล:** การปรับ Ridge/Random Forest ทำหลังเห็นผลบน Test Set และไม่ได้ทำ Cross-Validation จึงมีความเสี่ยงที่ผลบน Test ดูดีเกินจริง
8. **ไม่มี Time-Series Baseline อื่น** นอกจากสองตัวที่เพิ่มในหัวข้อที่ 2 เช่น ARIMA หรือ Seasonal Naive

### เกี่ยวกับการเตรียมข้อมูล

9. **Preprocessing ใช้ข้อมูลทั้งชุดก่อนแบ่ง Train/Test:** Min-Max Scaler, เพดาน Percentile (p90/p98) และอัตราส่วนปรับ Structural Break (ใช้ค่าเฉลี่ย 2021–2023) คำนวณจากข้อมูลทั้ง 152 เดือน ซึ่งรวมช่วง Test ด้วย อาจเกิด Data Leakage เล็กน้อย
10. **Vacancies ถูกจัดการต่างจาก Appointments:** Vacancies ใช้เพียง Cap p90 ไม่ได้ปรับ Structural Break แบบ Appointments (ฟังก์ชัน `process_two_structural_breaks` ถูกเรียกกับ Applicants และ Appointments เท่านั้น) แต่ Gap เปรียบเทียบสองชุดนี้โดยตรง
11. **Gap เป็นดัชนีสัมพัทธ์ ไม่ใช่ส่วนต่างของจำนวนคน:** ค่า 0–1 ถูก Scale แยกชุดด้วย min/max ของตัวเอง เกณฑ์ ±0.15 กำหนดเอง ไม่ได้ผ่านการ Validate กับนิยามขาดแคลนจริง
12. **ข้อมูลผู้สมัคร (Applicants) ถูกเตรียมไว้แต่ไม่ได้ใช้ในโมเดล**
13. ข้อความในโน้ตบุ๊กระบุช่วง Balanced เป็น "−0.14 ถึง 0.14" ที่ถูกต้องตามโค้ดคือ **−0.15 < Gap < 0.15**

## 11. แนวทางพัฒนาต่อ

- จัดการเดือน เม.ย. 2026 ของ Appointments เป็น **missing** (เช่น ใส่ `NaN` แล้ว interpolate หรือตัดเดือนนั้น) แทนการแปลงเป็น 0
- ทำ Preprocessing ใน Pipeline ที่ **fit เฉพาะชุด Train** แล้วค่อย transform ชุด Test และบันทึก Scaler/พารามิเตอร์เพื่อใช้กับข้อมูลใหม่
- ใช้ **`TimeSeriesSplit`** หรือ Walk-forward Validation แทนการแบ่ง 80:20 ครั้งเดียว
- ขยายไปทุกกลุ่มอาชีพ `1`–`9` และรายงานผลแยกตามอาชีพ
- ใช้ข้อมูลผู้สมัครเพิ่มเป็น Feature (เช่น อัตราส่วนผู้สมัครต่อตำแหน่งงาน)
- ทดลองโมเดลอนุกรมเวลาและ Gradient Boosting พร้อม Feature ตามฤดูกาล (เดือน/ไตรมาส)
- ทบทวนเกณฑ์ ±0.15 ให้อิงเปอร์เซ็นไทล์ของ Gap หรือนิยามเชิงนโยบาย เพื่อให้สัดส่วนคลาสสมดุลขึ้น
- เปรียบเทียบด้วยตัวชี้วัดที่เหมาะกับคลาสไม่สมดุล เช่น Balanced Accuracy และ Confusion Matrix
